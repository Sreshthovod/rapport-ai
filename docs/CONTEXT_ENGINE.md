# Context Engine Architecture & Specifications

The **Context Engine** is the intelligence abstraction layer sitting between platform adapters (e.g. WhatsApp Web) and AI Providers in **Rapport AI**. It ensures that AI model providers never consume raw DOM nodes or un-sanitized message strings.

---

## 1. Context Pipeline Architecture

```
Raw WhatsApp DOM / ChatMessage
        │
        ▼
[ Message Normalizer ] ──► Sanitize zero-width chars, format canonical types
        │
        ▼
[ Conversation Model Builder ] ──► Compute timeline stats, participants, health
        │
        ▼
[ Heuristic Tone Detector ] ──► Infer tone (Friendly, Professional, Romantic, etc.)
        │
        ▼
[ Conversation Stage Analyzer ] ──► Determine stage (Intro, Planning, Conflict, etc.)
        │
        ▼
[ Important Fact Extractor ] ──► Extract durable facts (dates, locations, preferences)
        │
        ▼
[ Context Summary Generator ] ──► Generate structured summary & pending questions
        │
        ▼
   StructuredAIContext ──► AIService / AIProvider
```

---

## 2. Data Flow

1. **Extraction**: `WhatsAppAdapter` extracts active chat messages into a `ConversationContext`.
2. **Message Normalization**: `MessageNormalizer.normalizeMessages()` converts raw messages into sanitized `CanonicalMessage[]`.
3. **Timeline & Model Assembly**: `ConversationModelBuilder.buildModel()` calculates timeline bounds, active duration, participant list, and conversation health metrics (`healthy`, `stale`, `one_sided`, `conflict`).
4. **Tone & Stage Classification**:
   - `HeuristicToneDetector.detectTone()` inspects message cues and user draft text.
   - `ConversationStageAnalyzer.inferStage()` evaluates conversation progress.
5. **Fact Extraction**: `ImportantFactExtractor.extractFacts()` extracts durable entities (names, locations, dates/times, preferences).
6. **Summary Generation**: `ContextSummaryGenerator.generateSummary()` aggregates findings into a `ContextSummary`.
7. **Delivery**: `ContextEngine.processContext()` returns a complete `StructuredAIContext` payload to `AIService`.

## 3. Public Interfaces

### `CanonicalMessage`
```typescript
export interface CanonicalMessage {
  id: string;
  sender: string;
  timestamp: number;
  text: string;
  direction: 'incoming' | 'outgoing';
  type: 'text' | 'system' | 'media' | 'unknown';
  quotedMessage?: QuotedMessageInfo | null;
  attachments: MessageAttachment[];
  reactions: MessageReaction[];
}
```

### `StructuredAIContext`
```typescript
export interface StructuredAIContext {
  conversation: ConversationModel;
  summary: ContextSummary;
  tone: ToneType;
  stage: StageType;
  recentMessages: CanonicalMessage[];
  extractedFacts: ExtractedFact[];
  pendingQuestions: string[];
}
```

## 4. Extension Points & Future Integrations

### Future Long-Term Memory Integration
The `ExtractedFact` objects generated by `ImportantFactExtractor` will automatically populate local IndexedDB storage (or Chrome sync storage) attached per contact ID. This persistent memory store will allow `ContextEngine` to attach historical preferences across past sessions.

### Future Vector Database Integration
When local embedding models or vector databases (e.g. Transformers.js / Wasm Vector Search) are integrated, the `ContextEngine` pipeline will run vector similarity searches against indexed message chunks to inject relevant historical conversation passages directly into `StructuredAIContext.summary`.
